What each click does

  1. 1
    Mode switcher. Offline = Writer + Reviewer both local, nothing leaves the machine. Hybrid = local draft, Claude improves and QCs. API = Claude end to end. Maps to config.py.
  2. 2
    Language toggle. SAS or R output from the same spec. R mode uses admiral-style pipelines; the harness swaps its pre-step templates, the agents get R style rules.
  3. 3
    Agent readout. Which model fills each role in the current mode — the same values written to the run log.
  4. 4
    Spec drop zone. Accepts the .xlsx workbook (later: define.xml). Shows the sheets it found.
  5. 5
    Parse spec. Runs the parser: splits copies vs derived and routes by Source. Spec errors (like a misaligned row) surface here, not downstream.
  6. 6
    Routing counts. Pre-flight check — how many variables take each path, which pre-steps will be built.
  7. 7
    Generate. Builds pre-steps, then sends each derived variable through the agent pipeline. Live status per variable; a run-log row is written whatever happens.
  8. 8
    Approve. Your sign-off on one block — recorded with your name and time in the audit trail. The human-in-the-loop gate.
  9. 9
    Send back to Improver. A flagged block returns to Claude with the QC finding attached and comes back rewritten for another review.
  10. 10
    Export program. Enabled only when every block is approved. Writes adsl.sas or adsl.R plus its run-log row and content hash.
  11. 11
    Commit to Git. One click for add–commit–push, with a generated message naming spec version, mode, and language.
  12. 12
    Comparison inputs. Production vs QC output — RTF, Word, or PDF, full or cut. Blocks are aligned by content, so a 4-page cut compares cleanly against a 12-page original.
  13. 13
    Run comparison. Deterministic parse-and-diff of every table cell, title, and footnote. No AI — results are exactly reproducible.
  14. 14
    Check against mock shell. Validates output structure (titles, columns, footnotes, decimal places) against the shell definition instead of a second output.
  15. 15
    Drill-down. Click any finding to see the two versions side by side with the difference highlighted. The verdict stamp is written to the audit trail.
